NexaForge SecureCode (Org AI Secure AppSec Gate) 7.0
====================================================
Version: 7.0.0

Code security (unchanged core, fixed)
- Global Claude Code skill (org-appsec-security), /security-gate and /sec-review commands
- Secure coding policy in global CLAUDE.md block and AGENTS.md
- PostToolUse fast heuristic check after every edit (Claude Code)
- Full/CI gate: Semgrep SAST, Trivy (vuln, misconfig, secret), Gitleaks, project tests, SARIF + JSON
- "Run Security Test" trigger with the standard report: verdict, findings table, fixed code, verify command
- Web + mobile test matrix, ZAP templates for authorized staging only, API BOLA/IDOR scaffold
- GitHub Actions and GitLab templates that install pinned, checksum-verified scanners

AI agent security (since 6.2)
- scripts/agent_guard.py: PreToolUse guard, fails closed. Blocks secret files (.env*, keys,
  cloud and agent credentials), pipe-to-shell, force push, reset --hard, root/home deletes,
  public repo creation, writes to shell startup files. Strict Markdown instruction-source mode
  for projects that contain claude_docs/.
- scripts/injection_watch.py: PostToolUse advisory scan of Read, WebFetch and MCP output for
  hidden Unicode and injection phrases.
- secgate.py agent scan: HIDDEN_UNICODE, INSTRUCTION_INJECTION, REPO_AGENT_HOOKS,
  MCP_AUTO_APPROVE, REPO_MCP_SERVERS, AGENT_HOME_OVERRIDE.
- config/agent-permissions.json: deny/ask rules merged into user settings, enableAllProjectMcpServers false.
- AGENTS.md rules for every agent; templates for Codex (config.toml, execpolicy rules) and strict projects.
- enterprise-managed-settings.example.json for admin-enforced policy.
- docs/AI-AGENT-SECURITY.md (incidents, per-tool setup, limits) and docs/SOURCES.md.

Honest limitations
- The per-edit check is heuristics, not SAST.
- Hooks and permission patterns reduce risk; they are not a sandbox or a security boundary.
- Native Windows has no Claude Code OS sandbox; use WSL2 or a devcontainer for untrusted repos.
- Claude Code gets the full hooks. Cursor, Codex, Gemini CLI and Antigravity get guard adapters that
  install-global.py --agent writes (in Codex and Gemini CLI an ask becomes a deny; Cursor's generic preToolUse hook is not wired to the
  guard yet, so Cursor's own file edits are not checked; Antigravity's behaviour when the hook itself fails
  is untested).
- Business logic, IDOR/BOLA and mobile runtime behaviour still need app-specific tests and review.
- This package is AppSec automation, not proof of vulnerability-free software.

7.0 guard
- scripts/agent_guard.py: positive model (normalizer, known everyday commands, paths resolved); every tool goes
  through it; tests/test_guard_positive_model.py and tests/test_fuzz_guard.py
- scripts/safe_git.py: git for the stop gate, the scanners and the engines without the repo's fsmonitor, hooks or
  drivers
- config/guard-policy.json (written by the installers, not shipped): owner mode asks with the literal command
  for force push, hard reset, force branch delete, public repo or gist and package publish; managed mode
  denies them; missing or malformed policy means managed. Asks are logged to .security/guard-audit.jsonl.
- scripts/adapters/cursor_hook.py and scripts/adapters/codex_hook.py; templates/cursor/hooks.json and
  templates/codex/hooks.json.
- scripts/stop_gate.py offers "Run Security Test" once per substantial change set (3+ code files or 40+ lines).

7.0 automated pentest
- scripts/report.py: REPORT.md and print-ready REPORT.html (optional PDF) with executive summary, scope and
  method, findings with CIA impact and retest outcome labels, attack chains, artifacts and limits
- scripts/report_lint.py: required sections, labels, evidence, no overclaims, no unmasked secrets
- scripts/local_dast.py: OWASP ZAP baseline or API scan of the developer's app on loopback only
- scripts/fix_pr.py: dry-run-first fix branch and draft PR, never the default branch, gitleaks on the diff

  concatenation, permitAll, CSRF off, Actuator, IDOR, mass assignment, @RequestBody without @Valid,

- secgate malware_scan (legacy audit): WEBSHELL_OBFUSCATED_EVAL, BACKDOOR_REQUEST_EXEC, REQUEST_DYNAMIC_CALL,
  PREG_REPLACE_EVAL, PHP_IN_UPLOAD_DIR, PHP_IN_IMAGE_FILE, SUSPICIOUS_OBFUSCATION
- secgate code_scan: MISSING_INPUT_VALIDATION, DEBUG_FLAG_FROM_REQUEST, TOKEN_FROM_USER_DATA,
  SHORT_NUMERIC_CODE, TOKEN_TOO_SHORT, PUBLIC_ENV_SECRET, SOURCEMAP_IN_PROD, AUTH_ROUTE_NO_THROTTLE,
  DENYLIST_FIX, PHP_DEPRECATED_API (up to PHP 8.5)
- secgate db_config_scan: DB_ROOT_USER, DB_EMPTY_PASSWORD, DB_NO_TLS, DB_BIND_ALL, DB_TRUST_AUTH,
  DB_GRANT_ALL, DB_SENSITIVE_COLUMN
- secgate default_cred_scan: WEAK_DEFAULT_CREDENTIAL (extended beyond seeders: compose, Spring, .env, connection
  strings, Django superusers), DEFAULT_SECRET_KEY, EXPOSED_ADMIN_PATH, EXPOSED_ADMIN_TOOL, SENSITIVE_WEBROOT_PATH,

- benchmark/spring-lab.json, legacy-lab.json, web-lab.json; run_lab.py scores every lab and its clean files
- docs/STANDARDS-COVERAGE.md; Legacy Audit step in the security-review skill

7.0 secret shield and MCP scan
- scripts/secret_shield.py: PostToolUse hook for Bash, PowerShell, Read, Grep, WebFetch and MCP output. Secret
  values are replaced in the output (updatedToolOutput) before the model sees them, with a block reason that
  names the source and type, never the value; .security/shield-audit.jsonl records it. `sweep` lists secrets
  already in Claude Code transcripts and project logs, masked, with revocation steps (read only).
- scripts/mcp_scan.py: offline scan of MCP configs (Claude Code, Cursor, Codex, Gemini CLI, VS Code): unpinned
  packages, pipe-to-shell, plain http, root or home folder access, inline secrets. Optional --connect NAME --yes
  lists a stdio server's tools, flags poisoning, and pins hashes in .security/mcp-lock.json (rug-pull check).
  secgate full and ci run the config mode on project configs.
- docs/SECRET-SHIELD-AND-MCP.md; tests/test_secret_shield.py and tests/test_mcp_scan.py

7.0 update mechanism and CI
- install-global.py: Task Scheduler task from an XML definition (catch-up, logon trigger, network, time limit,
  restart on failure); --update-timer for a systemd user timer (Persistent=true) or a launchd agent (RunAtLoad)
- scripts/updater.py: rate-limit back-off, incomplete download check, update-state.json for verify-global.py
- scripts/install-ci-scanners.ps1 (Windows twin of install-ci-scanners.sh) and scripts/ci/check_skips.py with
  tests/skip-allowlist.json: the CI test job installs the pinned scanners and fails on unexpected skips

7.0 outside review fixes
- scripts/adapters/gemini_hook.py (Gemini CLI BeforeTool) and scripts/adapters/antigravity_hook.py (Antigravity
  PreToolUse); templates/gemini/settings.hooks.json, settings.hooks.windows.json, templates/antigravity/hooks.json and hooks.windows.json
- scripts/engines/zap.py: OWASP ZAP 2.17.0 for local DAST through securecode setup --engine zap (Java 17+ checked,
  never installed)
- scripts/agent_guard.py: case-sensitive grep and rg options, awk regex literals are patterns (V7F-S2)
- ONE_PROMPT_INSTALL.md: one install route with the key fingerprint as the trust anchor; tests/test_v7_docs.py
